# 11 · Rust · 运算符与表达式

## 这个例子讲什么

Rust 的运算符与表达式规则：整数除法截断、四种显式溢出策略（`wrapping_` / `checked_` / `saturating_` / `overflowing_`）、位运算、`&&`/`||` 短路求值、块表达式直接产出值、`as` 显式转换会静默截断、复合赋值。

## 怎么跑

```
cd backend-roadmap/05-rust/basics/11-operators-and-expressions
cargo run --quiet
```

## 关键点

- `i32::MAX + 1` 在 debug 构建下 panic，release 下回绕；想行为确定就必须用四种显式方法之一，这是 Rust 比 C 更强调「溢出是业务决策」的地方。
- 没有隐式数值提升：`7 / 2` 是 `3`，想要浮点必须 `as f64`。
- `as` 是**截断转换**，`300i64 as u8` 得到 `44`，不报错也不 panic——这是最容易埋 bug 的运算符。
- 块 `{ ... }` 是表达式，最后一行（无分号）就是值，所以 `let x = { ... };` 合法。
- `&&` / `||` 严格短路，可用于「先判空再解引用」的惯用法。

## 和其他语言的差异

| 机制 | Go | Node.js | Python | Java | Rust |
|---|---|---|---|---|---|
| 整数溢出 | 静默回绕 | 双精度浮点，无整数溢出 | 任意精度整数 | 静默回绕 | debug panic / release 回绕，另有 4 种显式策略 |
| 隐式类型转换 | 无，需显式 | 弱类型自动转换 | 动态类型 | 有整型提升 | 无，必须 `as` |
| 条件必须是布尔 | 是 | 否（truthy） | 否（truthy） | 是 | 是 |
| 块表达式有值 | 否 | 否 | 否 | 否 | 是 |
| 三元表达式 | 无 | `? :` | `x if c else y` | `? :` | `if c { a } else { b }` |

Java 的 `int` 溢出静默回绕、Python 整数无上限、JS 只有双精度浮点（超过 2^53 丢精度），Rust 把溢出行为变成必须显式选择的 API。
