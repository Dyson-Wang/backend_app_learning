# 21 · Rust · 内存模型：GC / 所有权 / 生命周期

## 这个例子讲什么

Rust 没有 GC，靠**所有权 + 借用 + 生命周期**在编译期管理内存。本例用可观察输出演示：栈与堆、`Copy` vs `Move` vs `Clone`、函数传参的所有权转移、借用、`Rc` 引用计数、`Rc<RefCell<T>>` 内部可变性、`Drop` 的确定析构时机、以及生命周期标注。

## 怎么跑

```
cd backend-roadmap/05-rust/basics/21-memory-model
cargo run --quiet
```

## 关键点

- `i32` 是 `Copy`，赋值复制；`String` 是 `Move`，赋值后原变量**编译期失效**（不是运行时置空）。
- `Clone` 是显式深拷贝，有成本，必须自己写出来；Rust 不会偷偷复制。
- 借用 `&T` 不转移所有权；同一时刻「多个不可变借用」或「一个可变借用」二选一，这是编译期数据竞争防护。
- `Rc<T>` 是单线程引用计数（`Arc<T>` 才是多线程）；`Rc<RefCell<T>>` 才能共享可变，但 `borrow_mut` 冲突会在运行时 panic。
- `Drop` 在作用域结束时**确定性执行**，不需要 GC；这也是 Rust 能安全管理文件句柄、锁、连接的原因。
- 生命周期 `'a` 只是给编译器看的「引用有效范围」，不产生任何运行时开销。

## 和其他语言的差异

| 机制 | Go | Node.js | Python | Java | Rust |
|---|---|---|---|---|---|
| 内存回收 | 并发 GC | 分代 GC | 引用计数 + 循环 GC | 分代 GC | 所有权，编译期 |
| 值/引用 | 值语义 + 指针 | 全部引用 | 全部引用 | 基本类型值 / 对象引用 | 值语义 + 显式借用 |
| 析构时机 | `runtime.SetFinalizer`（不可靠） | GC 决定 | `__del__`（不可靠） | `finalize`（不推荐） | `Drop` 确定执行 |
| 数据竞争 | 运行时 `-race` 检测 | 单线程无 | GIL 保护 | 需自己加锁 | 编译期禁止 |

Go/Java/JS/Python 都有 GC，开发者不用管释放但会有停顿和不确定性；Rust 用编译期检查换来了「无 GC、无运行时、确定性析构」，代价是要和借用检查器搏斗。
