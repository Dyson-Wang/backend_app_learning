# 00 · 公共底座（语言无关）

这一层比多学一门语言重要。换语言时，下面这些东西一个字都不用改。

| 模块 | 目录 | 要掌握的判据 |
|---|---|---|
| 请求链路 | `request-lifecycle.md` | 能口述一个请求从 DNS 到响应的完整路径，并指出每段的超时在哪设 |
| SQL 与 PostgreSQL | `sql-and-postgres/` | 能解释隔离级别、索引失效、N+1、连接池耗尽 |
| Redis 与缓存 | `redis-and-cache/` | 能区分穿透 / 击穿 / 雪崩，能说清双写一致性的取舍 |
| 消息队列 | `message-queue/` | 能解释至少一次投递为什么必须做幂等、死信怎么进怎么出 |
| Docker / Nginx | `docker-and-nginx/` | 能写出反代 + 健康检查 + 超时的最小可用配置 |
| 可观测性 | `observability/` | 能用一个 trace id 串起网关日志、应用日志、慢查询 |

## 为什么单独一层

后端服务 = 固定的链路 × 语言特定的实现。网关、数据库、缓存、消息队列、日志这些是链路，应用服务层才是被 5 门语言替换的部分。只按语言分文件夹学语法，会遇到「每门语言都会写 HTTP handler，但没人教过连接池耗尽会发生什么」的断层。

`advanced/` 的 30 个生产场景，本质上就是这 6 块在压力下出问题的各种形态。

## 与 homelab 的关系

`~/workwork2/docker-services` 里已经跑着 PostgreSQL、MariaDB、Redis、Nginx 统一反代。这里的 SQL 脚本和 nginx 配置片段可以直接拿去用；涉及密钥、内网地址的部分一律用占位符，不写真实值。
