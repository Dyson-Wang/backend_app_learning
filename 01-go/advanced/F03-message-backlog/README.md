# F03 消息积压

## 问题复现

大促开始，队列从 0 涨到 100 万条。消费者日志一切正常，但延迟从 1 秒涨到 40 分钟。运维第一反应是「加机器」，加完发现没用——因为分区只有 3 个，第 4 个消费者分不到分区。

## 错误写法

```go
// 无脑扩容，但分区数没变
for i := 0; i < 10; i++ { go consume() }
```

## 正确写法

先算账：

```text
净消化速率 = 消费速率 - 生产速率
清空时间   = 积压量 / 净消化速率
```

再选手段：

| 手段 | 提速 | 代价 |
|---|---|---|
| 扩消费者 | 线性（受分区数限制） | 分区不够就白加 |
| 批量消费 | 5-10 倍单机吞吐 | 延迟上升、失败要重放整批 |
| 降级跳过 | 立即 | 丢数据，只能用于非关键消息 |

## 怎么验证

```bash
go run .
```

预期：`100 秒` → 3 消费者 `34 秒` → 批量 `10 秒` → 生产仍在灌时 `13 秒`。

## 和其他语言的差异

| 机制 | Go | Node.js | Python | Java | Rust |
|---|---|---|---|---|---|
| 并发消费 | goroutine | worker_threads | 多进程 | 线程池 | tokio task |
| 批量拉取 | `FetchMessage` | 同 | 同 | `poll(Duration)` | 同 |
| 分区限制 | Kafka partition | 同 | 同 | 同 | 同 |
