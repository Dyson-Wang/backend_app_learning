# 11 · Node.js · 运算符与表达式

## 这个例子讲什么

把算术 / 比较 / 逻辑 / 位运算、`&&`/`||`/`??` 的短路求值（用计数器实证右侧没执行）、优先级、复合赋值与逻辑赋值、整数「溢出」行为、`==` 隐式转换与三元表达式一次讲清，并点出 JS 里最容易踩的位运算 32 位回绕与浮点精度坑。

## 关键点

- `/` 是浮点除（不像 Go/Java 整数相除取整），`**` 幂运算右结合，`bigint` 支持任意精度算术。
- 短路：`false && f()` / `true || f()` 都不会调用 `f()`；`??` 只在 `null`/`undefined` 时取右侧，`0`/`''` 不会（与 `||` 不同）。
- `&&`/`||` 返回的是**操作数本身**而非布尔值，这是 JS 惯用写法 `port = input || 8080` 的基础。
- 位运算把操作数转成 **32 位有符号整数**，`2147483648 | 0` 回绕成 `-2147483648`；`>>>` 是无符号右移。
- `number` 是 float64：没有整数溢出，但超过 `MAX_SAFE_INTEGER`（2^53-1）会静默丢精度，超 `MAX_VALUE` 变 `Infinity`；`bigint` 才无上限。
- 逻辑赋值 `||=`/`&&=`/`??=` 同样短路；`??` 不能裸混 `&&`/`||`，必须加括号否则 SyntaxError。
- 优先级：`**` > 算术 > 比较 > `&&` > `||` > 三元 > 赋值；拿不准就加括号。
- `==` 会隐式转换（`0 == false`、`'' == 0` 都为真），一律用 `===`；`Object.is` 额外区分 `NaN` 与 `-0`。

## 和其他语言的差异

| 机制 | Go | Python | Java | Rust | Node.js |
|---|---|---|---|---|---|
| 整数除法 | `7/2 == 3` | `//` 整除、`/` 浮点 | `7/2 == 3` | `7/2 == 3` | `7/2 == 3.5`（无整除） |
| 幂 | `math.Pow` | `**` / `pow` | `Math.pow` | `pow` | `**` |
| 位运算 | `& \| ^ << >>` | 同 | 同 + `>>>` | 同 | `& \| ^ ~ << >> >>>` |
| 整数溢出 | 回绕（编译期常量报错） | 任意精度 int 不溢出 | `int` 回绕 | release 回绕 / debug panic | 无溢出（float64），位运算 32 位回绕 |
| 空合并 | 无（`if` 判断） | `or`（但会把 0 也当空） | 无 | 无 | `??`（只认 null/undefined） |
| 三目/三元 | 无 | `x if c else y` | `c ? x : y` | `if` 表达式 | `c ? x : y` |

Java 的 `>>>` 与 JS 同名同义；Python 的 `or` 会把 `0`/`''` 也当成假值取默认，JS 的 `??` 不会，这是迁移时最常写错的一处。Go/Rust/Java 的 `int` 都有固定宽度与回绕，JS 根本没有「整型」，只有双精度浮点 + 独立的 `bigint`。
