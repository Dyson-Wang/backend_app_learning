# F03 消息积压

## 问题复现

队列从 0 涨到 100 万条，消费者日志正常，但延迟从 1 秒涨到 40 分钟。加机器没用——分区只有 3 个，第 4 个消费者分不到。

## 错误写法

```js
for (let i = 0; i < 10; i++) worker();   // 分区没变，加消费者白搭
```

## 正确写法

```text
净消化速率 = 消费速率 - 生产速率
清空时间   = 积压量 / 净消化速率
```

| 手段 | 提速 | 代价 |
|---|---|---|
| 扩消费者 | 线性（受分区限制） | 分区不够就白加 |
| 批量消费 | 5-10 倍单机吞吐 | 延迟上升、失败重放整批 |
| 降级跳过 | 立即 | 丢数据 |

## 怎么验证

```bash
node index.mjs
```

预期：`100 秒` → `34 秒` → `10 秒` → `13 秒`。

## 和其他语言的差异

| 机制 | Go | Node.js | Python | Java | Rust |
|---|---|---|---|---|---|
| 并发消费 | goroutine | **worker_threads** | 多进程 | 线程池 | tokio task |
| 批量拉取 | `FetchMessage` | 同 | 同 | `poll(Duration)` | 同 |
| 分区限制 | Kafka partition | 同 | 同 | 同 | 同 |
