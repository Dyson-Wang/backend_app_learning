# 06 · 选修语言（体验式）

三门，只做「一个最小服务 + 一个生产场景」，不铺开全量 30 场景。目的是开眼界，不是集邮。

| 语言 | 什么时候才值得学 | 建议只做 |
|---|---|---|
| C# / .NET | 目标公司用微软栈 | `01 hello + HTTP 服务`，对照 Java 的写法差异 |
| Kotlin | Android 后端同栈 / 想看 JVM 上更现代的语言设计 | `01 hello + 协程`，对照 Java 虚拟线程 |
| Elixir / BEAM | 想理解 Actor 模型、进程隔离、let it crash、热更新 | `01 hello + 一个 supervision tree`，对照 Go 的 CSP |

Elixir 的认知价值最高：它是第五种并发思路，能让你重新理解「为什么其他语言需要那么复杂的容错代码」。但就业面窄，放在主线之后。

**不纳入**：C++（只有做基础设施 / 存储引擎才需要）、PHP / Ruby（除非接存量系统）、Scala / Clojure（生态收缩）。出现明确工作需求再学。
