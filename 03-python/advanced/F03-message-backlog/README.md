# F03 消息积压

## 问题复现

队列从 0 涨到 100 万条，消费者日志正常，延迟从 1 秒涨到 40 分钟。加机器没用——分区只有 3 个。

## 错误写法

```python
for _ in range(10):
    Process(target=consume).start()   # 分区没变，白加
```

## 正确写法

```text
净消化速率 = 消费速率 - 生产速率
清空时间   = 积压量 / 净消化速率
```

| 手段 | 提速 | 代价 |
|---|---|---|
| 扩消费者 | 线性（受分区限制） | 分区不够白加 |
| 批量消费 | 5-10 倍单机吞吐 | 延迟上升、重放整批 |
| 降级跳过 | 立即 | 丢数据 |

## 怎么验证

```bash
python3 main.py
```

预期：`100 秒` → `34 秒` → `10 秒` → `13 秒`。

## 和其他语言的差异

| 机制 | Go | Node.js | Python | Java | Rust |
|---|---|---|---|---|---|
| 并发消费 | goroutine | worker_threads | **多进程绕开 GIL** | 线程池 | tokio task |
| 批量拉取 | `FetchMessage` | 同 | 同 | `poll(Duration)` | 同 |
| 分区限制 | Kafka partition | 同 | 同 | 同 | 同 |
